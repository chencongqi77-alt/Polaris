## 这个项目是干什么的

这是一个 **MACP（Multi-Agent Collaborative Platform）** 的工程骨架，用来把“规划-生成-评估-沉淀”这种多智能体流程落到可运行的代码里。

现在阶段我们只做两件事：
- **把框架搭稳**：图怎么跑、怎么中断、怎么恢复、怎么测。
- **把技术打通**：LangGraph / checkpoint / human-in-the-loop / 记忆 / MCP（工具调用）这些底座先跑起来。

TM / SG / Eva 这些业务逻辑先不追求“聪明”，只要能接入就行。

---

## 目录速览（只看这三个就够）

- `app/`：核心代码（图、agent基类、接口定义、记忆模块都在这）
- `tests/`：回归测试（保证框架改动不把流程搞崩）
- `app_data/`：运行时数据（checkpoint sqlite、未来的缓存/本地数据）

说明文档在 `read/` 里：
- `first_read.md`：整体介绍 + 分工（你正在看）
- 另外三个文件分别介绍 `app/`、`tests/`、`app_data/`

## 我们两个人怎么分工（避免重复）

### 陈从启：架构/主线
- **冻结契约**：`MacpState`、节点输入输出、错误/trace字段怎么记。
- **把图跑稳**：LangGraph 主图、human-in-the-loop、checkpoint 的“中断-恢复”闭环。
- **把回归定下来**：至少一套 smoke 测试，保证每次改动都有底。
- **交接规范**：把“怎么跑、怎么测、怎么恢复”写清楚。

### 龚旭涵：基础设施/连通
- **MCP 打通**：真实 MCP server / tool registry / endpoint（现在 client 有了，但 server 需要对接）。
- **Qdrant 打通**：起服务、连通验证、写入/检索验证；后续再替换成真实 embedding（我已经换成智谱的embedding-3模型了，但是没有尝试调用过）。
- **环境配置**：`.env` / 端口 / key / 运行脚本，确保换机器也能跑。

注意：这里你需要去自己体验一个大概的MCP server这些东西怎么弄，但是你不用着急直接整合进我们的项目。
这个类似于我们之前的Infinity数据库，只要你大概知道怎么弄，可以快速部署到项目里面，然后你大概看看，对应我们项目的哪些部分里面，方便你后续直接添加。
然后你基本打通之后，看看我们项目的记忆模块，就是这些agent他们会共享记忆，还有长短时记忆这些东西。因为后面这个Qdrant就是搜取记忆模块的。
